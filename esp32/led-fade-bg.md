В този урок ще покажем как да използвате [PWM](https://www.arduino.cc/en/Tutorial/PWM) изход на ESP32, за да затъмните и изгасите LED. Тук нашите уроци започват да се различават от серията [Въведение в изхода](../arduino/intro-output.md) в раздела [Въведение в Arduino](../arduino/).

Важно е да се отбележи, че методът [`analogWrite`](https://www.arduino.cc/reference/en/language/functions/analog-io/analogwrite/) – който винаги е бил неправилно наименуван в библиотеката на Arduino, защото извежда импулсно-широчинна модулация (PWM), а не истинско аналогово напрежение – не е имплементиран в библиотеката на ESP32 Arduino. Вместо това има набор от PWM методи, които осигуряват допълнителен контрол, но на цената на сложност. Затова е добре, че досега сте разбрали PWM. Ако искате да си припомните, вижте нашето описание и гледайте видеоклиповете [тук](../arduino/led-fade.md#Pulse-width-modulation-PWM).

## PWM на ESP32

За да затъмните и изгасите LED с Arduino Uno (или други основни Arduino платки), използвайте метода [`analogWrite`](https://www.arduino.cc/reference/en/language/functions/analog-io/analogwrite/). Както вече знаем, `analogWrite` всъщност не подава аналогово напрежение към посочения пин, а вместо това използва импулсно-широчинна модулация (PWM). Тези PWM вълни се генерират от хардуерни таймери, които точно управляват пина `HIGH` и `LOW` въз основа на зададения работен цикъл. Така че, на Arduino Uno, `analogWrite(3, 127)` би излъчил стойност 5V за половината от периода (тъй като 127/255 = ~50%) на пин 3, а `analogWrite(3, 191)` би излъчил 5V за 75% от периода (тъй като 191/255 = ~75%). Частта от времето, през която сигналът е `HIGH`, се нарича работен цикъл. Arduino Uno (и Leonardo) имат само шест PWM изхода, защото разполагат с три таймера, всеки от които може да се използва за управление на два PWM пина.

На ESP32 всички 18 GPIO пина поддържат PWM, но подходът към програмирането е различен. Вместо `analogWrite`, ще използваме библиотеката [LED control (LEDC)](https://docs.espressif.com/projects/esp-idf/en/latest/esp32/api-reference/peripherals/ledc.html) на Espressif. По-конкретно, ще използваме абстрактен слой на базата на Arduino над това. Въпреки че наличната документация за библиотеката Arduino LEDC е малко оскъдна (всъщност, никога не съм намирал официални API документи), кодът е с отворен код и е достъпен тук ([.h файл](https://github.com/espressif/arduino-esp32/blob/a4305284d085caeddd1190d141710fb6f1c6cbe1/cores/esp32/ esp32-hal-ledc.h), [.c файл](https://github.com/espressif/arduino-esp32/blob/a4305284d085caeddd1190d141710fb6f1c6cbe1/cores/esp32/esp32-hal-ledc.c)). По-долу ще ви покажем как да я използвате.

### Библиотеката LEDC PWM

Библиотеката LEDC е написана предимно за управление на светодиоди, но може да се използва и за други цели, при които PWM вълните са полезни, като например възпроизвеждане на "музика" на пиезо високоговорители (точно както направихме с [`tone()`](https://www.arduino.cc/ reference/en/language/functions/advanced-io/tone/) в урока ни [просто пиано](../arduino/piano.md) и за задвижване на двигатели. Версията на Arduino на тази библиотека е част от основната библиотека ESP32 Arduino, така че не се нуждаете от никакви `include` изявления, за да я използвате.

За разлика от всички други I/O, които сме правили досега с Arduino, библиотеката LEDC работи с **канали**, а не с отделни **пинове**. За да приложите PWM вълна към пин, първо настройте канал с честота на PWM вълната и работен цикъл, а след това абонирайте или "прикачете" този пин към този канал. Няколко пина могат да се прикачат към един и същ канал и ще получават една и съща PWM вълнова форма. ESP32 има общо 16 канала, всеки от които може да генерира независима вълнова форма. Така че, макар и всички 18 GPIO пина да поддържат PWM, можем да управляваме само 16 от тях едновременно с **уникални** вълнови форми. Въпреки това, можем да прикачим всички 18 GPIO пина към един канал (или да ги разделим между каналите). В анимацията по-долу сме свързали всички 18 GPIO пина към канал 0.

![Анимация на всички 18 GPIO изходни пина, които се появяват и изчезват](assets/movies/Huzzah32_GPIOFadeTestAllPinsSimultaneously-Optimized3.gif)

Всички 18 GPIO пина са абонирани за един и същ PWM канал.

#### LEDC API

<!-- https://github.com/espressif/arduino-esp32/blob/96822d783f3ab6a56a69b227ba4d1a1a36c66268/tools/sdk/include/driver/driver/ledc.h -->

LEDC API има четири подходящи метода:

{% highlight C %}
/**
* Настройва канал (0-15), честота на PWM цикъл и PWM резолюция (1 - 16 бита) 
*/
double ledcSetup(uint8_t channel, double freq, uint8_t resolution_bits);

/**
* Записва стойност на работния цикъл в посочения канал. Стойността на работния цикъл трябва да бъде
* между 0 - 2^PWM резолюция
*/
void ledcWrite(uint8_t channel, uint32_t duty);

/**
* Прикача дадения пин към посочения канал (0-15)
*/
void ledcAttachPin (uint8_t pin, uint8_t channel);

/**
* Откачане на преди това прикачения пин
*/
void ledcDetachPin(uint8_t pin);
{% endhighlight C %}

Espressif [docs](https://docs.espressif.com/projects/esp-idf/en/latest/esp32/api-reference/peripherals/ledc.html#supported-range-of-frequency-and-duty-resolutions) подчертава, че честотата и резолюцията на PWM са взаимозависими; обаче те не описват точно тази връзка, а по-скоро дават примери:
- PWM честота от **5 kHz** може да има максимална разделителна способност от **13 бита**, което води до разделителна способност от ~0,012% или $$2^{13}=8192$$ дискретни нива на интензивност на LED
- PWM честота от **20 MHz** може да има максимална резолюция на заетост от **2 бита**, което води до резолюция от 25% или $$2^2=4$$ дискретни нива
- PWM честота от **40 MHz** може да има разделителна способност от 1 бит, което означава, че работният цикъл е фиксиран на 50% и не може да бъде регулиран

Ако се опитате да зададете несъвместими комбинации от честота и разделителна способност, на сериен монитор ще се появи следната грешка:

```
E (196) ledc: поисканата честота и разделителна способност не могат да бъдат постигнати, опитайте да намалите freq_hz или duty_resolution.
```

**АКТУАЛИЗАЦИЯ:** Открих, че тази грешка не се показва при използване на библиотеката Arduino LEDC, защото вътрешно функцията `ledcSetup` извършва проверка на границите и, ако прагът бъде превишен, задава максималните стойности ([link](https://github.com/espressif/arduino-esp32/blob/ a4305284d085caeddd1190d141710fb6f1c6cbe1/cores/esp32/esp32-hal-ledc.c)).

#### Връзка между PWM честотата и резолюцията

Защо и как PWM честотата и резолюцията са взаимозависими? Въпреки че документацията за ESP32 [docs](https://docs.espressif.com/projects/esp-idf/en/latest/esp32/api-reference/peripherals/ledc.html#supported-range-of-frequency-and-duty-resolutions) е, за съжаление, оскъдна, ето обяснението.

Представете си, че имате часовник (CPU часовник или таймер, няма значение), който работи с определена честота, и искаме да зададем честота и разделителна способност на PWM вълната. Максималната честота на PWM вълната е ограничена от часовника. Ако тя е 40 MHz, тогава максималната честота на PWM също е 40 MHz. Не можем да произведем PWM вълна, по-бърза от часовника ни.

Но какво става с **разделителната способност**? Разделителната способност всъщност се отнася до това колко можем да разделим един период на PWM вълната на различни работни цикли. И ето какво трябва да знаете: разделянето на PWM вълната изисква CPU часовник, работещ на $$PWM_{freq} * 2^{PWM resolution}$$. Защо? Защото за да генерирате тези работни цикли, трябва да можете да създадете тези времеви сегменти. А единственият начин да го направите е с още по-бърз часовник. (Забележка: това е *идеалният* случай. В действителност всичко има допълнителни разходи и затова според мен обикновено е добре часовникът на CPU да е с 30-50% по-бърз от най-бързата ви PWM честота; пак би било добре, ако ESP32 ни дадеше уравнението).

Ето един визуален пример, който, надявам се, ще изясни концепцията. Тук можете да видите часовника, работещ на 40 MHz, PWM честотата на 1 MHz и различни PWM резолюции. За всяка от PWM резолюциите съм поставил техните "времеви сегменти" – това е моментът, в който генераторът на PWM вълни би могъл потенциално да зададе PWM вълната HIGH или LOW за даден работен цикъл. Забележете как с увеличаването на PWM резолюцията се увеличава и нуждата от все по-бърз CPU часовник (за да може да отговори на тези все по-взискателни резолюции на работния цикъл).

Така например, ако искаме да зададем PWM резолюция от 5 бита, работеща на 1 MHz, тогава ни е необходим часовник, работещ на най-малко 32 MHz. Ако искаме резолюция от 6 бита на 1 MHz, тогава надвишаваме нашата часовникова скорост от 40 MHz.

За повече примери за PWM вижте този [PDF](assets/images/PWM_FrequencyAndDutyCycle.pdf), който сме създали.

#### Каква PWM честота и резолюция да използвам?

И така, каква PWM честота и резолюция трябва да използвате? Това зависи от контекста. Не забравяйте, че Arduino Uno осигурява PWM вълнова форма от ~490 Hz при 8 бита, въпреки че пинове 5 и 6 могат да управляват вълнова форма при 980 Hz ([link](https://www.arduino.cc/reference/en/language/functions/analog-io/analogwrite/)). А това е повече от достатъчно бързо, за да се постигне плавно преливане между различни нива на яркост на LED. Така че винаги можете да започнете оттам (~490 Hz честота, 8-битова резолюция) и след това да експериментирате.

#### Използване на LEDC API

Въпреки донякъде объркващата (и непълна) документация, използването на LEDC API е относително просто:
- Първо извикайте `ledcSetup`, за да конфигурирате канал с конкретна PWM честота и резолюция
- След това прикачете пин към този канал, използвайки `ledcAttachPin`
- Накрая, за да зададете действителната стойност на работния цикъл на даден канал, извикайте `ledcWrite` (последната функция е донякъде аналогична на `analogWrite`; обаче, `ledcWrite` работи върху абстракцията "канал", докато `analogWrite` работи върху пинове).

### Алтернативи на LEDC

В допълнение към модула LEDC, ESP32 поддържа две други опции за аналогов изход:

1. **Модул за сигма-делта модулация** ([docs](https://docs.espressif.com/projects/esp-idf/en/latest/esp32/api-reference/peripherals/sigmadelta.html)) . В сравнение с PWM, [сигма-делта модулацията](https://en.wikipedia.org/wiki/Delta-sigma_modulation) има вградена обратна връзка, за да се опита да минимизира грешките на таймера и да произведе по-точни вълни. В Arduino IDE има пример за сигма-делта. Отидете на File -> Examples -> ESP32 -> AnalogOut -> SigmaDelta. Подобно на библиотеката LEDC, вие свързвате пинове към предварително конфигурирани сигма-делта канали.

2. **Истински аналогов изход** чрез цифрово-аналогов (DAC) преобразувател ([docs](https://docs.espressif.com/projects/esp-idf/en/latest/esp32/api-reference/peripherals/dac.html)). ESP32 има два 8-битови DAC, свързани към GPIO25 (канал 1) и GPIO26 (канал 2). DAC драйверът позволява тези канали да бъдат настроени на произволни напрежения, което означава, че най-накрая можете да произвеждате красиви синусоидални напрежения, вместо скучните квадратни вълни. В интернет има много примери за хора, които използват DAC на ESP32 за възпроизвеждане на музика. Ето едно упътване от [Xtronical](https://www.xtronical.com/introduction-to-dac-audio/), но потърсете в интернет за още!

В този урок обаче ще се съсредоточим върху използването на библиотеката LEDC за създаване на PWM вълни, които ще затъмняват и изсветляват LED.

#### Стъпка 1: Настройка на PWM стойностите

Първо, нека настроим някои PWM константи. Чувствайте се свободни да експериментирате с тях.

{% highlight C %}

const int PWM_CHANNEL = 0; // ESP32 има 16 канала, които могат да генерират 16 независими вълнови форми
const int PWM_FREQ = 500; // Припомнете си, че Arduino Uno е ~490 Hz. Официалният пример на ESP32 използва 5000 Hz
const int PWM_RESOLUTION = 8; // Ще използваме същата резолюция като Uno (8 бита, 0-255), но ESP32 може да достигне до 16 бита 

// Максималната стойност на работния цикъл въз основа на PWM резолюцията (ще бъде 255, ако резолюцията е 8 бита)
const int MAX_DUTY_CYCLE = (int)(pow(2, PWM_RESOLUTION) - 1);
 
{% endhighlight C %}

#### Стъпка 2: Настройте другите константи и променливи

След това настройте другите константи и променливи. Това е подобно на другите Arduino програми, които сме написали.

{% highlight C %}
// Номерирането на пиновете на Huzzah32 е малко странно, затова винаги е полезно да се консултирате с диаграмата на пиновете
// Вижте диаграмата на пиновете тук: https://makeabilitylab.github.io/physcomp/esp32/
const int LED_OUTPUT_PIN = 21;

const int DELAY_MS = 4; // забавяне между стъпките на затъмняване
int _ledFadeStep = 5; // степен на затъмняване на всеки цикъл
{% endhighlight C %}

#### Стъпка 3: Функцията setup()

В `setup()` ще настроим PWM канал и ще свържем пин към този канал.

{% highlight C %}
void setup() {

// Настройва канал (0-15), честота на PWM цикъл и PWM резолюция (1 - 16 бита)
// ledcSetup(uint8_t channel, double freq, uint8_t resolution_bits);
ledcSetup (PWM_CHANNEL, PWM_FREQ, PWM_RESOLUTION);

// ledcAttachPin(uint8_t pin, uint8_t channel);
ledcAttachPin(LED_OUTPUT_PIN, PWM_CHANNEL);
}
{% endhighlight C %}

#### Стъпка 4: Напишете fade loop()

А fade `loop()` е почти същият като оригиналния fade loop (от [тук](../arduino/led-fade.md)); обаче, сега използваме `ledcWrite`, за да променим работния цикъл на даден канал, вместо `analogWrite`, за да променим работния цикъл на даден пин.

{% highlight C %}
void loop() {

// fade up PWM на даден канал
for(int dutyCycle = 0; dutyCycle <= MAX_DUTY_CYCLE; dutyCycle++){ 
ledcWrite(PWM_CHANNEL, dutyCycle);
delay(DELAY_MS);
}

// затъмняване на PWM на даден канал
for(int dutyCycle = MAX_DUTY_CYCLE; dutyCycle >= 0; dutyCycle--){
ledcWrite(PWM_CHANNEL, dutyCycle); 
delay(DELAY_MS);
}
}
{% endhighlight C %}
